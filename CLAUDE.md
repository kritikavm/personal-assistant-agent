## Project

A local personal assistant agent for one user on one Mac, built with the Claude Agent SDK (Python). It reads Google Calendar (read-only) and a local JSON task list, writes a daily morning brief, sets timed alerts in one Apple Reminders list ("Agent Reminders"), captures tasks in plain language, and answers questions about the day. It is also a portfolio project showing agent loops, tool use, state, permissions, human-in-the-loop, guardrails, structured outputs, failure handling and evals.

## Non-negotiable rules

1. **Google Calendar is read-only.** Use only the `calendar.events.readonly` OAuth scope, check it at startup, and write no calendar write code. The only writes allowed: the local task files, the agent's own `data/` files, and the Reminders list "Agent Reminders". Never touch any other list.
2. **Zero additional AI cost.** Use the Claude subscription via the Agent SDK only. No API key, no usage credits, no other paid model. Refuse to start if a billing credential is present. If usage is unavailable, stop with a clear error. Never fall back.

## Key decisions so far

- Claude reasons; plain Python acts. Agent tools are read-only or `submit_*`/`propose_*` proposals. Plain code does every write, after validation and, where required, confirmation.
- Structured output goes through `submit_*` tools (pydantic-validated, one retry on invalid output).
- Default-rule reminders are computed deterministically by code. Claude only adds capped "extra" reminders with a reason, and writes the brief.
- Reminders and notifications use AppleScript via `osascript`. The list name is hard-coded, and reminders are tracked in `state.json` plus a `[pa:<kind>:<key>]` marker.
- Scheduling: `launchd` LaunchAgent, regenerated by `assistant schedule install`. `doctor` warns if the schedule and preferences differ.
- Data lives in `./data/` in the repo (gitignored). The Google token is kept in the macOS Keychain.
- The project lives in `~/Developer/personal-assistant-agent`, outside iCloud-synced folders, so `data/` stays on the Mac. It moved there from `~/Documents/VibeCoding` on 2026-10-14; work only in the new folder. `doctor` warns if `data/` is in an iCloud-synced folder.
- The Google Cloud OAuth project is set to *In production* (unverified, personal use) so refresh tokens don't expire every 7 days.
- Quiet hours: move a reminder to the end of quiet hours if that's still before its event or deadline, otherwise to just before quiet hours start.
- Step limits: `add` 6, `ask` 10, `run` 15.
- Default task priority is `medium`. Completed tasks move to `completed_tasks.json`, grouped by completion date.
- The morning brief also shows as a macOS notification. A failed scheduled run shows a failure notification.
- Dry run writes only a log line marked `dry_run`.
- If the calendar is unavailable, existing meeting and birthday reminders are kept.
- Invalid `state.json` (FR-23a): block all Reminders writes like FR-23, copy the bad file to `backups/`, still write the brief, show the reason in the brief and `doctor`. Only `assistant state rebuild`, run and confirmed by the user, rebuilds from `[pa:]` markers. Never rebuild automatically. A missing `state.json` is handled the same way if the list already holds `[pa:]` items; otherwise the run starts fresh.
- Tech stack: Python 3.12, `uv`, Typer, pydantic v2, `google-api-python-client`, `google-auth-oauthlib`, `keyring`, PyYAML.
- Model: every flow uses `MODEL = claude-sonnet-5-5` (one constant in `agent/runner.py`, no fallback). Sessions are locked down beyond `setting_sources=[]`: skills, slash commands and the CLI's built-in plugins off, built-in agents allowlisted, init checked (`apiKeySource == "none"`), stop on any `rejected` or `overage` rate-limit event, no saved transcripts.
- S-9 resolved: the user confirmed via Anthropic's help center that Agent SDK usage draws from subscription limits. The billing startup check stays.
