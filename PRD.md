# Personal Assistant Agent — Product Requirements Document

**Status:** Draft for review · **Phase:** 1 (not yet built) · **Last updated:** 2026-10-10

---

## 1. Problem

My meetings live in Google Calendar, my tasks live somewhere else, and nothing looks at both together. So I:

- miss deadlines that weren't on my calendar
- over-commit on days that are already full of meetings
- set reminders by hand, inconsistently, or not at all
- start each day without a clear view of what matters most

## 2. Vision

A local, private assistant that reads my calendar and my task list, reasons across them, and keeps me on top of my day. Each morning it gives me a short brief and sets timed reminders on my Mac. During the day I can ask it questions in plain language.

It starts small and grows in phases. It is read-only toward my calendar, it can only write to places I've explicitly approved, and it costs nothing beyond my existing Claude subscription.

It is also a portfolio project that demonstrates agent loops, tool use, state, permissions, human-in-the-loop, guardrails, structured outputs, failure handling and evals.

## 3. Target user

One person (me): a single user on a single Mac, with Google Calendar, the Apple Reminders app, and a Claude subscription. Comfortable editing a JSON/YAML file and running a terminal command. Not designed for multiple users or teams.

## 4. Use cases

| # | As a user, I want to… | Example |
|---|---|---|
| U1 | Get a morning brief at 8 AM | "3 meetings, 2 tasks due today, 1 overdue. Focus: finish the cover letter before the 2 PM interview." |
| U2 | Capture a task in plain language | "buy milk tomorrow" → task in *shopping*, due tomorrow |
| U3 | Get reminders at the right times without setting them myself | Meeting at 3 PM → reminder at 2 PM in "Agent Reminders" |
| U4 | Ask about my day | "What does my day look like?" |
| U5 | Ask what to prioritize | "What should I focus on today?" |
| U6 | See what's slipping | "What is overdue?" |
| U7 | Check whether something fits | "Do I have time for a 2-hour task today?" |
| U8 | Trigger a run on demand while testing | `run now` |

## 5. Phase 1 scope

1. **Read Google Calendar** events for today and the next 7 days (read-only).
2. **Local task file** (JSON) with: title, description, category, priority, deadline, status, and optional estimated duration.
3. **Plain-language task capture**, with the agent assigning a category (e.g. shopping, job, plants, personal, errands) and pulling out the deadline and priority.
4. **Editable preferences file** for brief time and reminder rules (see §8).
5. **Scheduled daily run at 8 AM**, plus a manual `run now` command.
6. **Each run:** read calendar, tasks and preferences → write a morning brief → plan reminders → create timed alerts in the **"Agent Reminders"** list in Apple Reminders.
7. **Q&A** over calendar and tasks (U4–U7).

**Who does what**

| AI (Claude via Agent SDK) | Plain code (Python) |
|---|---|
| Categorizing captured tasks | Reading and writing the task, preferences and state files |
| Reasoning across calendar and tasks | Calling the Google Calendar API (read-only) |
| Adding **extra** reminders for important items (with a reason) | Computing the **default-rule** reminders from preferences (deterministic) |
| Writing the morning brief | Creating reminders in "Agent Reminders" |
| Answering questions | Scheduling (brief-time job) and the `run now` command |
| | Validation, deduplication, logging, error handling |

## 6. Non-goals (not in Phase 1)

- RAG / document search
- Email of any kind
- Creating, editing or deleting calendar events
- Multi-agent setups
- A web or desktop UI (interaction is through the CLI and the Reminders app)
- Cloud hosting (runs locally on my Mac only)
- Multiple users, shared calendars management, or mobile apps
- Writing to any Reminders list other than "Agent Reminders"

## 7. Functional requirements

### 7.1 Calendar (read-only)
- **FR-1** Fetch events from today through 7 days ahead from the calendars named in preferences: **primary**, plus a **birthdays calendar if one exists**. If the configured birthdays calendar isn't found, the agent skips it, logs a note, and carries on.
- **FR-2** For each event, capture title, start/end, all-day flag, location, and calendar source. Don't store attendee emails or descriptions unless needed for reasoning.
- **FR-3** Treat as birthdays: events on the birthdays calendar, events Google marks with the birthday event type, and all-day events with "birthday" in the title.

### 7.2 Task file
- **FR-4** Tasks are stored in a local JSON file (`tasks.json`). Each task has:

  | Field | Type | Required | Notes |
  |---|---|---|---|
  | `id` | string | yes | generated by code |
  | `title` | string | yes | |
  | `description` | string | no | |
  | `category` | string | yes | assigned by AI, editable by me |
  | `priority` | `high` \| `medium` \| `low` | yes | defaults to `medium` when unclear |
  | `deadline` | ISO 8601 datetime or date | no | |
  | `status` | `todo` \| `in_progress` \| `done` | yes | |
  | `estimated_minutes` | integer | no | |
  | `created_at` / `updated_at` | ISO 8601 | yes | set by code |
  | `completed_at` | ISO 8601 | when done | set by code |

- **FR-5** Code validates every write against this schema. Invalid AI output is rejected, never written.
- **FR-6** Writes are atomic (write to a temp file, then rename), and the previous version is backed up.

### 7.3 Task capture
- **FR-7** `add "<text>"` turns plain language into a task. The AI returns **structured output** (JSON matching the schema) with category, priority, deadline and estimated duration inferred. If priority can't be inferred, it defaults to **medium**.
- **FR-8** Relative dates ("tomorrow", "next Friday") are resolved against the local time zone. "Next <weekday>" means that weekday in the following week (said on Wednesday 2026-10-28, "next Friday" is 2026-11-06); "this <weekday>" means that weekday in the current week ("this Friday" is 2026-10-30). The agent states the assumption it made when it shows the parsed task (FR-10), including with `--yes`.
- **FR-9** If the input is ambiguous (e.g. no clear deadline for something that sounds time-sensitive), the agent asks one short clarifying question or saves the task with no deadline, and says which it did.
- **FR-10** The agent shows me the parsed task and its assumptions, then asks before saving (human-in-the-loop). A `--yes` flag skips only the question: the parsed task and assumptions are still printed, then saved.
- **FR-11** I can also mark tasks done and edit or delete them through CLI commands.
- **FR-11a** When a task is marked done, code moves it out of `tasks.json` into `completed_tasks.json`, grouped by completion date (local time zone), e.g. `{"2026-10-10": [ ...tasks ]}`. The move uses the same validation and atomic writes as FR-5/FR-6, and `completed_at` is set. Completed tasks are not used for reminders but can be read for Q&A.

### 7.4 Daily run
- **FR-12** A local scheduler (macOS `launchd`) triggers the run at the brief time in preferences (default 8:00 AM). If the Mac was asleep (not shut down), the run happens at next wake. After changing `morning_brief.time`, I run `assistant schedule install` to update the schedule; `assistant doctor` warns if the installed schedule and preferences differ.
- **FR-13** `run now` performs the same run on demand. `run now --dry-run` plans and prints everything and writes nothing except a log line marked `dry_run`.
- **FR-14** Each run:
  1. Loads preferences, tasks and calendar events.
  2. Produces a **morning brief** (structured: summary, today's schedule, due today, overdue, suggested focus, free time blocks). It is printed, saved to `briefs/YYYY-MM-DD.md`, added to "Agent Reminders" as an item at the brief time from preferences, and shown as a **macOS notification** (via `osascript`) with a neutral summary only, e.g. "Morning brief ready: 3 meetings, 2 tasks due", with no titles or details (S-15). The full brief is in the file. Saved briefs older than 30 days are deleted automatically.
  3. Builds a **reminder plan**: code computes the default-rule reminders deterministically from preferences, and the AI adds extra reminders as structured output: a list of `{title, fire_at, source_type, source_id, reason}`.
  4. Code validates the extras (future times only, within the 7-day window, per-item cap), applies quiet hours to all reminders, and creates the reminders.
- **FR-15** **Idempotent:** running twice doesn't create duplicates. Code keeps a local state file mapping `source_id + fire_at` to the created reminder ID, and updates or removes agent-created reminders when the source event or task changes or is completed.
- **FR-16** The agent only ever updates or deletes reminders that it created itself (tracked in the state file) and that are in "Agent Reminders".

### 7.5 Reminder planning
- **FR-17** Default rules come from preferences (§8) and are applied by plain code, so the same inputs always give the same default reminders. The AI may add extra reminders for important items (e.g. an interview also gets a reminder the day before), each with a one-line `reason`.
- **FR-18** A per-item cap on extra reminders (from preferences) prevents reminder spam.

### 7.6 Q&A
- **FR-19** `ask "<question>"` answers using current calendar, tasks and preferences. It covers at least: my day, focus/prioritization, overdue items, and whether a task of a given length fits today (based on free time between meetings and working hours).
- **FR-20** Answers cite the specific events and tasks they rely on. If data is missing or a fetch failed, the answer says so instead of guessing.
- **FR-21** Q&A is read-only, except for task changes that I explicitly ask for and confirm.

### 7.7 Failure handling
- **FR-22** If Calendar is unreachable or auth has expired, the run continues with tasks only, and the brief clearly says calendar data is missing. Existing meeting and birthday reminders are kept, not removed (missing data doesn't mean the events were cancelled).
- **FR-23** If Reminders access is denied, the "Agent Reminders" list is missing, or the list is not an On My Mac list (S-14), the agent skips all reminder writes with a clear message. The brief is still written, and the reason appears in the brief and in `doctor`. It does not create or move the list or touch any other list. (The list is created once by me during setup.)
- **FR-24** If Claude subscription usage is unavailable or exhausted, the run stops with a clear error (see §9, Rule 2). Plain-code steps that don't need AI still run: the run is logged as failed, and a scheduled run also shows a macOS notification naming the failure type (there is no terminal to see it).
- **FR-25** Malformed AI output is retried once with the validation error, then the step fails cleanly. Nothing invalid is written.
- **FR-26** Every run writes a local log: start/end, steps, tool calls, reminders created/updated/removed, and errors. Logs hold actions, IDs, statuses and errors only (S-13), and log files older than 30 days are deleted automatically.

## 8. Preferences file

A human-editable file (`preferences.yaml`), validated at startup. Invalid values produce a clear error naming the field.

```yaml
timezone: America/Los_Angeles      # IANA zone
morning_brief:
  time: "08:00"
working_hours:
  start: "09:00"
  end: "18:00"
calendars:
  - primary
  - birthdays                      # used only if it exists; skipped otherwise
reminders:
  meetings:
    before: 60m                    # 1 hour before start
  tasks_with_deadline:
    morning_of_due_day: "08:00"
    before_deadline: 60m
  birthdays:
    evening_before: "20:00"
  extra_reminders:
    allowed: true                  # agent may add extras for important items
    max_per_item: 2
    examples: ["interviews get a reminder the day before"]
categories: [shopping, job, plants, personal, errands]
default_priority: medium
quiet_hours:                       # no reminders fire in this window
  start: "22:00"
  end: "07:00"
```

**Quiet-hours rule:** a reminder that would fire during quiet hours moves to the end of quiet hours if that is still before its event or deadline; otherwise it moves to just before quiet hours start.

## 9. Safety and privacy requirements

### Rule 1 — Calendar is read-only; writes are limited to two approved places

- **S-1** OAuth requests only the minimum read-only scope: `https://www.googleapis.com/auth/calendar.events.readonly`. No write-capable scope is ever requested.
- **S-2** **Technical enforcement**, not just prompting:
  - At startup, code checks the scopes on the stored token. If any scope beyond the allowed read-only set is present, the agent refuses to run.
  - The calendar tool exposed to the agent only wraps `events.list` and `events.get`. No create/update/delete functions exist in the codebase.
- **S-3** The only write access anywhere:
  1. the local task files (`tasks.json`, `completed_tasks.json`, and their backups), and
  2. the Apple Reminders list named exactly **"Agent Reminders"**.
  (Plus the agent's own local operational files: briefs, logs, state.)
  The macOS notification only displays text and stores nothing. It is sent by plain code with a fixed command, not by a general shell tool the agent can call.
- **S-4** The Reminders tool has the list name hard-coded. It doesn't accept a list name as a parameter, and it checks the target list before every write. Any other list is never read or written. All text passed to `osascript` is handled as described in S-18.
- **S-5** The agent runs with an explicit tool allowlist in the Agent SDK. Built-in general tools (shell, arbitrary file write, web access) are disabled. A permission hook denies any tool call outside the allowlist and logs it.

### Rule 2 — Zero additional AI cost

- **S-6** AI runs only through the Claude Agent SDK, authenticated with my Claude subscription.
- **S-7** No paid API key, usage credits, pay-as-you-go or other paid model. At startup, code refuses to run if `ANTHROPIC_API_KEY` (or another billing credential, e.g. cloud-provider Claude settings) is present in the environment, so the SDK can't silently use billable access.
- **S-8** If included usage is unavailable or exhausted, the agent stops with a clear error. There is no fallback to billable usage or to another model.
- **S-9** *Resolved:* Anthropic's help center (support.claude.com, "Use the Claude Agent SDK with your Claude plan") confirms Agent SDK usage draws from my subscription limits. The startup check in S-7 stays in place.

### Privacy

- **S-10** All data (tasks, preferences, briefs, logs, OAuth tokens) stays on my Mac.
  - OAuth tokens are stored in the macOS Keychain, not in plain files or the repo.
  - The Google OAuth client secret file is stored in `data/secrets/` (gitignored, permission `600`) and is never committed.
  - The `data/` folder and its subfolders are `700` and their files `600`, readable only by me. `doctor` warns if anything is looser.
- **S-11** Only the data needed for a request is sent to Claude, and only via the Agent SDK. No other third-party services.
- **S-12** Secrets and personal data files are git-ignored. The repo ships with sample/fake data only. Secret scanning (`gitleaks`) runs on every commit and before every push, and blocks it if a secret is found.
- **S-13** Logs store actions, IDs, statuses and errors only: no event titles, task text, descriptions, questions, answers or brief content. Validation errors are logged as field paths, not values. Logs and saved briefs are kept for 30 days, then deleted automatically.
- **S-14** "Agent Reminders" must be an **On My Mac** list, not an iCloud list, so reminder titles don't leave the Mac. Every run checks the list's account before writing. If it isn't On My Mac, all reminder writes are skipped (as in FR-23), the brief is still written, and the reason is shown in the brief and in `doctor`.
- **S-15** Notifications can appear on the lock screen, so they show only a neutral summary (e.g. "Morning brief ready: 3 meetings, 2 tasks due"), with no event titles, task text or other details. Alerts shown by the Reminders app itself include the reminder title; this is accepted as a known limitation, and setup tells me to set macOS notification previews to *When Unlocked*.
- **S-16** Agent SDK session history: during the build, check whether the SDK saves session transcripts under `~/.claude/`. If it does, turn that off if possible; otherwise document the location in SECURITY.md and add it to the cleanup steps (S-20).

### Hardening

- **S-17** **Untrusted data / prompt injection.** All content from calendar events, tasks, preferences values and stored files (`state.json`, briefs, and any AI-written text such as extra-reminder `reason` fields) is treated as data, never instructions, on every run. It is schema-validated on load, reaches Claude only as tool-result JSON, and the system prompt says to ignore any instructions inside it. A prompt-injection eval checks this (§10.5).
- **S-18** **AppleScript injection.** All text passed to `osascript` (reminder titles, notes, notification text) is passed as script arguments, never string-interpolated into the script. Scripts are fixed in the code and read their inputs via `on run argv`.
- **S-19** **Supply chain.** Dependency versions are pinned in the `uv` lock file, only official packages are used, and `pip-audit` runs before each release.
- **S-20** **Kill switch.** SECURITY.md documents the steps to stop the agent completely: uninstall the schedule, delete the Keychain token, and revoke the app's access in Google account settings.

## 10. Success criteria

Phase 1 is done when:

1. **Daily run works:** for 7 consecutive days the 8 AM run produces a brief, a macOS notification and correct reminders with no manual fixes.
2. **Reminder accuracy:** on calendar and task fixtures:
   - default-rule reminders (plain code) match the preference rules 100% (right item, right time)
   - extra reminders (AI) are correct in ≥ 7 of 8 eval cases
   - zero duplicates on repeated runs
3. **Capture and brief accuracy:**
   - **Capture:** on an eval set of ≥ 30 plain-language inputs, ≥ 90% get the correct category and deadline, and ≥ 80% get the correct priority.
   - **Morning brief:** across 6 eval cases, zero invented events or tasks in every case (100%), and the full brief checklist (EVALS.md) is met in ≥ 5 of 6 cases.
4. **Q&A quality:** answers to the four core question types are correct against fixtures and cite their sources. When data is missing, the answer says so instead of making it up.
5. **Safety tests pass (100%):**
   - A token with a write scope is rejected.
   - No calendar write function is reachable.
   - Attempts to write to any Reminders list other than "Agent Reminders" are blocked.
   - Tool calls outside the allowlist are denied.
   - The agent refuses to start when an API key is present.
   - A reminder and a notification with a malicious title (AppleScript/shell syntax) are stored or shown literally, and nothing else runs (S-18).
   - The reconciler never edits or deletes a reminder that isn't in `state.json`.
   - `run now --dry-run` writes nothing except its log line.
   - Built-in SDK tools and my user settings are absent from every session (`setting_sources=[]`).
   - **Prompt-injection eval:** fake events and tasks containing injected instructions cause no blocked or out-of-allowlist tool calls, no proposed task changes, no extra reminder that references the injected text, and the planted canary phrase appears in no output (reminder, brief or answer) (S-17).
6. **Failure handling:** simulated calendar outage, missing Reminders permission, exhausted usage, and malformed AI output each produce the documented behavior.
7. **Cost:** $0 in additional AI spend.

Each eval set is run once. If a non-safety set misses its target by one case, it may be rerun once and the rerun result is used, with both runs logged. The prompt-injection and failure-handling sets must pass on every run, with no reruns. Details are in EVALS.md.

## 11. Roadmap

Future phases are **planned, not built.**

**Phase 2: smarter reminders and capture**
- Learn from what I snooze, complete or ignore to tune reminder timing
- Detect conflicts and overload ("you have 6 hours of tasks and 2 free hours")
- Suggest time blocks for tasks in free slots (shown as suggestions only; calendar stays read-only)
- Quicker capture (e.g. a macOS shortcut or a Reminders inbox the agent reads)
- Recurring tasks
- An end-of-day review

**Phase 3: more approved tools, each with its own permissions**
- Email (e.g. read-only Gmail to spot deadlines and action items), with its own minimum scope and permission checks
- Plant care (watering schedules per plant, with reminders)
- Each new tool gets its own scoped credentials, an allowlist entry, safety tests, and an explicit approval step before it's turned on
